# 제공 버티컬 시뮬레이터 통합

사용자가 제공한 `ctu-rack-vertical.zip`의 TypeScript 코어·단위 변환·입력 검증·기준 테스트를 `src/vertical/`에 통합했습니다. [원본 README](vertical-reference.md)는 참고 자료로 보존했습니다. ZIP의 설치 스크립트를 실행하거나 별도 앱으로 중복 설치하지 않았습니다.

## 유지한 모델

- 최소 피치 = 운송물 높이 + 인출 여유 + 빔 두께.
- 선반 인계면(i) = 첫 선반 높이 + (i−1) × 실제 피치.
- 랙 구조 총높이 = 첫 선반 높이 + 단수 × 실제 피치. 마지막 단 위 상부 빔을 포함합니다.
- 총높이 고정 모드는 실제 피치를 `(총높이−첫 선반 높이)/단수`로 역산합니다.
- 랙 구조 높이와 천장 이격, 모든 단의 최저/최고 작업면, 마스트 최대 상승 전고를 별도로 검사합니다.
- 최대 단수의 공간/로봇 제한과 한 단 추가에 필요한 공간·작업면 높이를 표시합니다.

첨부 6단·2,699 mm 예제는 원본의 테스트 가정이며 현장 사양으로 확정하지 않습니다. 앱에서 예제 버튼 또는 엄격한 `_mm` JSON 가져오기를 사용하면 m 단위 모델로 변환하고 확인 상태를 해제합니다.

## 수정한 부분

- 원본은 로봇 전고가 천장보다 커도 `maxLevels.max`가 양수일 수 있었습니다. 전체 전고 불합격은 운영 가능한 최대 단수 0으로 반영했습니다.
- 알 수 없는 JSON·null·누락 구조·NaN·Infinity·수치 넘침을 검사하고 단수/스캔을 1~100으로 제한했습니다. 무제한 배열 생성을 방지하고 제한 범위를 명시합니다.
- 고정 피치·고정 총높이·최소 피치 세 가지 모드에 맞는 최대 단수 판정을 추가했습니다. 고정 총높이에서 단수를 바꾸면 피치가 달라지므로 단순한 고정 피치 식으로 최대 단수를 계산하지 않습니다.
- 연속 승강 범위와 동일 순번의 고정 단 높이 매칭을 구분했습니다. 로봇 내부 피치가 랙 피치와 다르더라도 연속 승강형이라는 이유만으로 불가 판정하지 않습니다.
- 웹 비교 카드·단별 표·측면도·3D 모두 `resolveVerticalGeometry`의 같은 실제 피치와 구조 총높이를 사용합니다.
- 실제 로봇 외형·인계 사양과 도면/건물/랙 확인 근거가 없으면 검토 필요 상태를 유지합니다. 원본의 `feasible` 산술 결과와 현장 확인 완료를 구분합니다.

이 수직 계산은 정적 기하 검토이며 DES 계산과 별개입니다. 제조·AMR 이벤트와 운영 KPI는 Python SimPy에서 계산합니다. 높이별 가변 하중, 마스트 처짐·동적 간섭, 소방·내진·바닥/랙 구조 검토는 추가 현장 검증이 필요합니다.
