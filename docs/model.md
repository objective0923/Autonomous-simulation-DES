# 입력 및 계산 모델

## 공통 단위와 파일

프로젝트는 `schemaVersion: "1.0"`, 고유 `id`, `modelVersion`, `assumptions`, 지도·자원·운영 조건을 담는 JSON입니다. 내부 기본 단위는 거리 **m**, 시간 **s**, 무게 **kg**, 배터리 **Wh**, 전력 **W**입니다. mm를 입력하려면 1,000으로 나누고, min/h는 각각 60/3,600을 곱해 초로 변환합니다. 각 ID는 프로젝트 전체에서 유일해야 합니다. 지원하지 않는 버전, 누락 참조, 잘못된 값·용량은 실행 전에 거부합니다.

## 지도와 자원

`nodes`의 x/y는 m이며 `kind`는 통과·상하차·대기·충전·교차로를 구별합니다. `edges`에는 from/to, 실제 이동 길이, 폭, 속도 제한, 양방향 여부를 지정합니다. `allowedRobotTypes`를 지정하면 해당 유형만 통과합니다. `disabled` 구간은 경로에서 제외합니다. 같은 물리 통로의 별도 양방향 구간은 동일한 `zoneId`를 사용하세요. 기본 구역은 양 끝 노드의 순서와 무관하게 공유됩니다.

경로는 통행 가능 구간의 예상 이동시간 합이 가장 작은 경로입니다. 구간마다 정지 상태에서 가속·감속하는 보수적인 모델이며, 중간 노드마다 `turnTime`을 더합니다. 최고 속도 v, 가속도 a, 길이 d일 때 d ≤ v²/a이면 `2√(d/a)`, 이외에는 `2v/a + (d-v²/a)/v`초입니다. 실제 회전반경·옴니 주행·스윕 영역은 계산하지 않습니다. 적재물 외곽을 별도 모델링하지 않으므로 로봇 width/length는 적재물까지 포함한 유효 외곽으로 입력하세요. 통로 폭 검사는 width를 사용합니다.

지도 객체의 회전 단위는 도입니다. 벽·기둥과 객체 겹침은 배치 검토 경고이며, 그래프 경로를 자동으로 차단하지 않습니다. 장애물을 통과하는 연결을 사용자가 삭제·비활성화해야 합니다. PNG/JPG/PDF 배경은 이미지 표시 폭·높이(m)와 기준 위치를 지정합니다. Three.js 3D 검토를 제공합니다. CAD 의미 추출은 후속 범위입니다.

## 생산·조립·재고

`buffers`의 capacity는 품목에 관계없는 **수량 합계** 기준입니다. `initialInventory`는 품목별 초기 수량입니다. 개별 슬롯·적재중량·직렬번호·유한 용기 순환은 아직 별도 모델이 없습니다.

`processes`는 입력 버퍼의 `inputRequirements`를 소비하고, 처리시간 후 출력 버퍼에 `outputProduct`를 `outputQuantity`만큼 생산합니다. 부품 부족, 배출 공간 부족, 공유 작업자/설비(`workerResourceId`) 사용 중이면 대기합니다. 출력 공간을 생산 시작 시 예약하는 보수적인 blocking-before-service 정책입니다. `isFinal: true` 공정의 출력만 완제품 생산 KPI로 집계하며 중간재 생산과 운송 완료를 구별합니다. 공정 처리 중 소비된 부품과 생산 예정 수량은 재공품으로 해석해야 합니다.

운송 규칙은 출발·도착 버퍼, 품목, 배치 수량, 단위중량, 우선순위와 요청 후 기한을 설정합니다. 출발 재고와 도착 공간을 예약하고 적재/하역 완료에 따라 물리 재고 위치가 변경됩니다. 가득 찬 목적지에는 예약하지 않으며 원래 위치에서 대기합니다. 묶음·대체 목적지·빈 용기 회수 전용 정책은 후속 범위입니다.

## 시간 분포

분포 선택은 공정마다 독립적이며 모든 시간 출력은 초입니다.

| kind | 매개변수 및 범위 |
| --- | --- |
| fixed | value ≥ 0 |
| uniform | 0 ≤ min ≤ max |
| triangular | 0 ≤ min ≤ mode ≤ max |
| normal | mean, sd ≥ 0, 0 ≤ min ≤ max; 범위 밖 샘플은 재추출하는 절단 정규분포 |
| lognormal | 로그 공간 평균 mu(유한수), 로그 공간 표준편차 sigma ≥ 0 |
| exponential | mean > 0 |
| empirical | values: 비어 있지 않은 0 이상 초 단위 실측 샘플, 균등 복원 추출 |

절단 정규분포 추출 한도를 넘으면 매개변수 오류를 표시합니다. 극단적/넘침 값은 거부합니다. SimPy 서버는 프로젝트 시드와 공정 ID를 SHA-256으로 결합한 Python Random 독립 흐름을 사용합니다. 엔진 버전이 바뀌면 같은 시드여도 난수열이 바뀔 수 있으므로 입력·엔진 버전을 함께 비교해야 합니다. 다른 공정의 난수 추출 횟수는 이 공정의 난수열을 바꾸지 않습니다.

## 로봇·배터리·충전

로봇 유형은 유효 크기, 중량·수량 한계, 지원 품목(`*`는 전체), 공차·적재 속도, 가속도, 중간 정차/회전, 상하차시간을 지정합니다. 배터리 임계값은 `reserveWh ≤ chargeBelowWh < chargeToWh ≤ batteryCapacityWh`입니다. 전력은 W, 에너지는 `power × seconds / 3600` Wh입니다. 작업 선택 시 공차·적재·상하차와 작업 종료 후 호환 충전기까지의 에너지를 확인합니다. 교통 대기 등 실제 지연은 추가 전력을 소비하므로 고갈 예외 가능성을 결과에서 확인하세요.

충전기는 접속 노드, 동시 점유 용량, 유한 대기 공간, W 단위 출력, 도킹·이탈시간, 호환 유형을 가집니다. 상수 출력으로 충전하며 SOC 구간별 곡선·배터리 열화는 지원하지 않습니다. 초기 배터리·충전 임계값을 바꿔 충전 경쟁을 확인할 수 있습니다.

## 지표·통계·재현

`warmup` 이후부터 `duration`까지가 측정 구간입니다. 완료 작업 지연의 평균과 nearest-rank P95는 측정 구간에 완료된 작업의 요청→완료 시간을 사용하며 미완료 작업을 포함하지 않습니다. 미완료 수량은 별도 표시합니다. 요청이 안정화 구간에 발생해도 완료가 측정 구간이면 해당 작업의 전체 지연을 포함합니다.

상태 시간은 측정 구간과 겹치는 부분을 집계합니다. 로봇 상태 비율 분모는 로봇 한 대의 측정 시간, 충전기 이용률 분모는 용량×측정 시간, 버퍼 점유율은 용량×측정 시간에 대한 물리 재고의 시간 적분입니다. 예약 수량은 물리 점유율과 구별합니다. 빈 이동 거리 비율은 공차/(공차+적재)이며 측정 경계에 걸친 이동 집계 방법은 엔진 구현 및 검증 기록을 참조하세요.

반복 실행은 원본 초기 상태로 새 엔진을 만들어 서로 다른 시드로 실행합니다. 평균 신뢰구간은 독립 실행에 대한 Student t 평균 95% CI입니다. 1회 실행에서는 표준편차나 신뢰구간을 만들지 않습니다. 개별 운송 지연의 P95는 평균 신뢰구간과 다른 지표입니다. 실측 검증을 하지 않은 통계는 입력 가정에 대한 모형 결과입니다.

실행 결과에는 입력 프로젝트, 시드, 모델·엔진 버전, 측정 구간, 가정, 이벤트와 상태 이력을 저장합니다. 기록 재생은 상태 이력을 읽으며 재실행은 저장된 입력으로 새 엔진에서 계산합니다. 결과 이력은 교육·소규모 비교에 적합하며 대규모 이벤트 스트리밍 저장은 후속 범위입니다.

## 서버와 웹 재생

Python SimPy가 시간과 이벤트를 관리합니다. 웹은 전체 계산을 요청한 뒤 반환된 상태 이력을 재생합니다. 웹의 일시정지·계속·배속은 재생 커서에만 적용하며 서버에서 진행 중인 계산을 일시정지하는 기능은 아닙니다. 요청 취소는 브라우저 응답 적용을 취소하며 이미 시작한 서버 계산은 자원 한도 내에서 마무리될 수 있습니다. SimPy 클래스는 별도로 step/run_until API를 제공하며 자동 검증에서 일괄 실행과 결과 일치를 확인합니다.

상태 이력이 4,000개를 넘으면 재생 기록을 적응적으로 간추리고 HISTORY_SAMPLED 경고를 남깁니다. 이벤트 로그와 KPI는 유지합니다. 이벤트 반복 한도·배터리 고갈 등의 진단 오류는 정상 완료와 구분해야 합니다.
