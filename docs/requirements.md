**CROIS AMR·제조물류 DES 시뮬레이터 개발 요구사항**

작성일: 2026-10-24 · 문서 버전: 0.1 · 용도: Codex 개발 전달용

이 문서를 기준으로 제조라인과 AMR 물류를 함께 계산하는 시뮬레이터를 개발한다. 사용자가 공간 배치, 로봇 사양, 생산조건, 운영 정책을 변경하여 필요한 AMR 대수·충전기 수·버퍼 용량과 예상 처리량·지연·병목을 비교할 수 있어야 한다. 아래 완료 기준은 개발 후 확인할 기준이며, 현재 구현 완료를 의미하지 않는다.

개발에는 다음 공통 원칙을 적용한다.

- 기존 저장소가 제공되면 해당 구조와 기술을 먼저 확인한다. UI, DES 엔진, 시나리오 데이터, 결과 분석을 분리한다.
- 1차 화면은 2D 평면도 편집과 실행 모니터링을 기준으로 한다. 3D 화면을 추가할 수 있도록 계산 상태와 렌더링을 분리한다.
- 시뮬레이션 시간과 화면 재생 시간을 분리한다. 화면 배속·프레임 수·렌더링 여부가 계산 결과에 영향을 주지 않도록 한다.
- 내부 기본 단위는 m, s, kg, Wh, W로 통일한다. 화면의 mm, min, h 등의 입력은 변환 규칙과 단위를 명시한다.
- 설비·충전기·통로·버퍼를 각각 용량과 점유 상태가 있는 자원으로 취급한다. 자원 획득·예약·해제 규칙을 명시한다.
- 계산에 사용하는 가정, 초기 상태, 난수 시드, 모델·엔진 버전을 실행 결과에 기록한다. 예시 수치는 테스트용 가정임을 표시한다.
- 본 단계는 처리량·물류 운영·병목 검토를 대상으로 한다. 실제 센서 인식, SLAM, 모터 제어 및 안전 성능 검증은 별도 범위로 둔다.

1. **AMR 시뮬레이터 개발 — 전체 사용자 흐름**
   - 프로젝트 생성, 공간 편집, 사양·운영조건 설정, 시뮬레이션 실행, 결과 조회·비교의 흐름을 제공한다.
   - 여러 대의 AMR과 여러 종류의 운송물을 동일 공간에서 운영할 수 있게 한다.
   - 지도에 로봇 위치·상태·작업·배터리, 운송물 위치, 설비·버퍼 점유, 진행 중 경로를 표시한다.
   - 편집 화면, 실행 모니터링 화면, 결과 분석 화면을 제공한다. 실행 중 입력 변경은 금지하거나 명시적인 개입 이벤트로 기록한다.
   - **완료 기준:** 예제 프로젝트를 열어 조건 설정부터 실행, 병목 확인, 결과 저장까지 한 흐름으로 사용할 수 있다.

2. **DES 기반 시뮬레이션 엔진**
   - 생산 완료, 운송 요청, 배차, 이동 구간 진입·이탈, 상하차, 충전, 고장·복구 등의 이벤트로 상태를 변경한다.
   - 이벤트 큐는 시각·동시 발생 시 처리 우선순위·등록 순서에 따라 일관되게 처리한다. 다음 이벤트 시각으로 시뮬레이션 시간을 진행한다.
   - 시작, 일시정지, 계속, 초기화, 이벤트 단위 진행, 종료 시각 설정, 화면 없이 실행하는 기능을 제공한다.
   - 시간·자원·재고·로봇 상태의 기준값은 엔진이 소유한다. UI는 엔진 상태를 표시하며 독립적으로 수량이나 KPI를 증가시키지 않는다.
   - 난수 생성은 시드로 제어한다. 논리상 필요한 0시간 이벤트는 허용하되 동일 시각 무한 반복을 감지하고 원인을 표시한다.
   - **완료 기준:** 같은 입력·초기 상태·시드·엔진 버전으로 실행하면 이벤트 순서와 결과가 재현되며, 화면 배속 또는 렌더링 여부를 바꿔도 결과가 같다.

3. **로봇 이동 노드 및 랙·팔레트 등 공간 배치**
   - 노드, 연결 구간, 랙, 팔레트, 대차, 제조라인, 상하차 위치, 버퍼, 벽·기둥·장애물, 로봇 대기 위치를 배치한다.
   - 드래그, 회전, 복사, 삭제, 다중 선택, 정렬, 격자 맞춤, 확대·축소, 좌표·치수 입력을 제공한다.
   - 객체마다 고유 ID, 이름, 좌표, 방향, 층 ID, 크기, 종류, 접근 노드 또는 인계 위치를 설정한다.
   - 이동 노드는 단순 통과·분기·상하차·대기·충전 등 용도를 구분한다. 연결 구간은 시작·종료 노드와 실제 이동 길이를 가진다.
   - 지도상 겹침, 경로 단절, 접근 노드 누락, 통로 폭 부족을 검사한다. 검사 결과의 오류와 검토 필요 사항을 구분한다.
   - **완료 기준:** 사용자가 배치한 출발지·목적지로 실제 운송 작업을 실행할 수 있고, 연결되지 않은 목적지는 실행 전 또는 배차 시 원인이 표시된다.

4. **충전기 배치**
   - 충전기를 지도에 배치하고 위치, 방향, 크기, 접속 노드, 도킹 방향, 동시 충전 가능 대수, 지원 로봇 종류를 설정한다.
   - 충전 전 대기 위치와 접근·이탈 경로를 지정한다. 대기 공간도 수용 가능한 대수를 제한한다.
   - 충전기와 일반 대기 위치를 별도 객체로 관리하며, 충전기의 점유·고장·예약 상태를 표시한다.
   - 충전기 접근 불가, 호환 로봇 없음, 도킹 공간 부족 등을 검사한다. 충전 소비·회복 계산과 운영 정책은 11번에서 처리한다.
   - **완료 기준:** 충전기 위치·수량·대기 공간 변경이 접근 거리, 충전 대기 및 운영 결과에 반영된다.

5. **제조라인 이벤트 처리 및 난수 설정**
   - 투입, 가공, 조립, 검사, 포장, 배출, 재작업 등의 공정과 공정 간 연결을 구성한다. 품종별 공정 순서와 생산계획을 설정한다.
   - 처리시간, 도착 간격, 품종 비율, 배치 수량, 불량 발생, 고장 간격·복구시간 등 서로 다른 변동 요인을 구분한다.
   - 시간 설정에는 고정값, 균등분포, 삼각분포, 절단 정규분포, 로그정규분포, 지수분포, 실측 샘플 기반 입력을 지원한다. 각 분포의 매개변수 의미·단위·허용 범위를 화면에 명시한다.
   - 공정별 처리시간이 음수가 되지 않도록 검증한다. 분포는 사용자가 선택하며 실측 근거 없이 모든 공정에 같은 분포를 강제하지 않는다.
   - 조립 시작 조건으로 부품 종류·필요 수량, 선행 공정 완료, 설비·작업자 가용 여부를 설정한다. 예: A 부품 2개와 B 부품 1개, 조립 설비와 작업자가 모두 확보되면 시작한다.
   - 완제품 일정 수량 도달, 재고 하한 도달, 작업자 호출 등으로 운송 요청을 생성한다. 같은 조건으로 미처리 요청이 중복 생성되지 않도록 한다.
   - 부품 부족, 배출 버퍼 포화, 후공정 정지 시 공정의 대기·정지와 재개 조건을 정의한다. 교대·공용 설비 장애처럼 여러 공정에 함께 영향을 주는 이벤트도 처리한다.
   - **완료 기준:** 부품 부족으로 조립이 대기하고, 보충 완료 후 재개되며, 배출 버퍼가 가득 차면 지정한 정책대로 생산이 정지한다. 난수 시드 변경 시 변동 결과가 달라지고 같은 시드로 재현된다.

6. **로봇 사양 및 동작시간 모델**
   - 저상형 AMR, 팔레트 AMR, 롤러 AMR, 자율지게차 등 로봇 유형을 사양 템플릿으로 등록한다.
   - 차체·적재물 크기, 적재중량·수량, 지원 운송물, 적재·공차 속도, 가감속, 회전속도·회전반경, 일반·옴니 이동 가능 여부를 설정한다.
   - 도킹·이탈, 정렬, 승강, 적재, 하역, 대차 연결·분리 등의 시간을 작업 종류별로 설정한다.
   - 이동시간은 경로 길이와 구간 속도 제한, 가감속·회전·대기시간을 반영한다. 상하차 동작 중 점유할 로봇·설비·공간도 지정한다.
   - 로봇 상태는 대기, 공차 이동, 적재, 적재 이동, 하역, 도킹, 교통 대기, 설비 대기, 충전 대기, 충전, 고장 등으로 구분하고 각 상태의 시간을 기록한다.
   - **완료 기준:** 속도·상하차시간·적재 조건을 변경하면 작업 완료시간과 처리량이 달라지고, 운송 조건을 충족하지 않는 로봇은 배차되지 않는다.

7. **운송 작업 생성 및 배차**
   - 작업에 출발지, 목적지, 운송물 종류·수량·중량, 요청 시각, 우선순위, 기한, 요구 로봇 능력을 기록한다.
   - 작업 상태를 대기, 예약, 배차, 수행 중, 완료, 실패, 취소로 관리한다. 작업과 로봇·운송물의 연결 관계를 추적한다.
   - 선입선출, 긴급 우선, 최근접 적합 로봇, 예상 완료시간 기준 등의 배차 정책을 선택할 수 있게 한다.
   - 배차 전에 로봇 능력, 경로 연결, 운송물 존재, 목적지 수용 가능 여부, 배터리와 충전소 복귀 가능성을 확인한다.
   - 입고, 공정 간 이송, 출고, 보충, 빈 팔레트·대차 회수를 작업 유형으로 지원한다. 여러 요청의 묶음 운송은 로봇 수용능력과 인계 조건을 만족할 때 허용한다.
   - 취소·실패·재배차 시 중복 수행을 막고 반환 가능한 예약을 해제한다. 이미 적재한 운송물의 현재 위치·소유 상태는 보존한다.
   - **완료 기준:** 한 작업이 여러 로봇에 중복 배차되지 않고, 동일 물동량에 대해 배차 정책별 결과를 비교할 수 있다.

8. **경로 탐색 및 교통 제어**
   - 노드·연결 구간 기반 경로 탐색을 제공하고, 일방통행·양방향·속도 제한·통행 금지·로봇 종류별 제한을 반영한다.
   - 적재물 포함 외형, 회전 공간, 통로 폭을 기준으로 통과 가능한 경로를 판정한다. 1차는 보수적인 구역 점유 방식으로 구현할 수 있다.
   - 교차로와 좁은 통로를 공유 자원으로 예약·점유·해제한다. 동일한 물리 통로를 양방향 연결로 표현해도 공통 점유 제한을 적용한다.
   - 대기·양보·진입 우선순위·우회 규칙을 설정한다. 혼잡을 반영하는 경로 선택 정책을 확장할 수 있게 한다.
   - 서로 자원을 기다리는 교착 상태와 단순 지연을 구분한다. 원인 로봇·자원을 표시하고 안전하게 가능한 예약 해제·우회·재배차를 수행한다. 자동 해소가 불가능하면 복구 필요 상태로 기록한다.
   - **완료 기준:** 단일 통로에서 서로 마주 오는 로봇이 동시에 진입하지 않고, 교차로 예약·해제가 작동한다. 경로 없음이나 교착으로 작업이 멈췄을 때 원인이 식별된다.

9. **랙·버퍼·재고 및 운송용기 관리**
   - 랙의 열·단·슬롯, 슬롯별 치수·허용중량·제품 호환 조건, 접근 위치를 설정한다.
   - 슬롯과 버퍼는 비어 있음, 예약, 점유, 사용 불가 상태를 구분한다. 예약 중인 칸을 다른 작업에 중복 할당하지 않는다.
   - 제품·부품·팔레트·대차의 식별정보, 수량, 현재 위치, 이동 중 상태를 추적한다. 적재·하역 완료 이벤트에 맞춰 재고 위치를 갱신한다.
   - 고정 위치, 빈 위치 우선, 가까운 위치 우선 등 보관 정책과 선입선출 등의 출고 정책을 설정한다.
   - 공정별 입력·출력 버퍼의 용량과 재고 하한·상한을 지정한다. 목적지 예약 시점과 가득 찬 경우 출발 대기·대체 목적지·임시 버퍼 사용 정책을 명시한다.
   - 빈 팔레트·대차·박스를 유한한 순환 자원으로 다루어 빈 용기 부족과 회수 지연이 생산에 반영되게 한다.
   - **완료 기준:** 운송·조립·불량·폐기 내역에 따라 수량 변화가 설명되고, 슬롯 초과 점유·중복 예약·이유 없는 재고 생성 또는 소실이 발생하지 않는다.

10. **주변 설비 및 작업자 연동**
    - 엘리베이터, 자동문, 컨베이어, CTU, 리프트, 작업자를 용량·처리시간·상태·대기열이 있는 자원으로 구현한다.
    - 요청, 사용 예약, 준비 확인, 진입 또는 인계, 완료 확인, 이탈·해제의 절차를 설정한다.
    - 엘리베이터는 층 연결, 현재 층, 탑승 가능 대수·중량, 문 개폐·이동시간, 호출·대기 정책을 가진다.
    - CTU·컨베이어는 인계 위치, 처리 가능 운송물, 입출고시간, 버퍼 용량과 연계한다. 하역 가능한 상태일 때 인계하도록 한다.
    - 작업자 수, 작업 가능 공정, 수작업 시간, 교대·휴식과 여러 작업의 자원 경쟁을 반영한다.
    - 초기 구현은 가상 설비 모델로 구성한다. 실제 FMS·WMS·MES 연결을 위한 어댑터 경계는 분리하되 실장비 연결은 별도 단계로 진행한다.
    - **완료 기준:** 설비 또는 작업자가 사용 중이면 작업이 대기하고, 가용 상태가 되면 재개된다. 설비 처리능력 변경이 대기시간과 전체 처리량에 반영된다.

11. **배터리 소모 및 충전 운영**
    - 배터리 용량과 초기 잔량을 설정하고 적재·공차 이동, 승강·상하차, 대기 등의 상태별 에너지 소모를 계산한다.
    - 충전 출력 또는 잔량 구간별 충전속도, 충전 시작·종료 잔량, 최소 운행 잔량, 여유 시간 충전 정책을 설정한다.
    - 작업 배차 시 예상 작업 에너지와 작업 종료 위치에서 충전소까지 필요한 에너지, 설정한 예비 잔량을 함께 확인한다.
    - 충전기 선택에 호환성·거리·가용 여부·예상 대기시간을 반영한다. 여러 로봇이 동시에 충전을 요청하면 점유 용량과 대기 공간을 준수한다.
    - 충전 시작 전 도킹, 충전 완료 후 분리·이탈 시간을 반영한다. 충전 중단 허용 여부와 작업 복귀 조건도 설정한다.
    - 배터리 고갈은 예외 이벤트로 처리하고 잔량을 음수로 계산하지 않는다.
    - **완료 기준:** 같은 로봇 대수에서 충전기 수·위치·충전 정책 변경에 따른 가동 가능 대수, 충전 대기, 물류 지연을 비교할 수 있다.

12. **운영 일정, 장애 및 복구**
    - 일·교대별 운영시간, 휴식, 생산계획 변경, 품종 전환, 계획 정비를 일정으로 설정한다.
    - 로봇·설비·충전기의 고장 간격과 복구시간을 고정값·분포·수동 이벤트로 지정한다. 사람·장애물로 인한 통로 차단과 지연을 설정한다.
    - 고장 시 수행 중 작업의 중단·재개·재시작·재배차 정책을 정의한다. 정비 인력이나 복구 설비가 제한된 경우 복구 대기열을 반영한다.
    - 고장 로봇은 제거·견인 이벤트 전까지 실제 위치의 점유를 유지한다. 작업 재배차만으로 운송물이나 장애물이 사라지지 않게 한다.
    - 장애 시각, 영향받은 작업, 복구시각, 중단시간, 미처리 작업을 기록한다.
    - **완료 기준:** 장애가 재고·작업·예약의 중복이나 소실을 일으키지 않으며, 복구 이후 규정한 정책대로 운영이 재개된다.

13. **성과지표 및 병목 분석**
    - 생산 완료 수량과 운송 완료 작업 수를 구분하여 시간당·교대당·일별 처리량을 표시한다.
    - 운송 요청부터 완료까지의 시간, 배차 대기, 공차 이동, 적재 이동, 상하차, 교통 대기, 설비 대기, 충전 대기를 분리한다.
    - 로봇 상태별 시간·비율, 공차 거리 비율, 충전기 이용률, 설비 이용률, 버퍼 점유율, 최대 대기열을 표시한다.
    - 자재 부족 및 배출 공간 부족으로 인한 생산 중단시간, 작업 기한 초과, 미완료 작업·종료 시 잔여 재고를 표시한다.
    - 평균과 함께 P95 지연시간 등 분포 지표를 제공한다. P95와 반복 실행 결과의 신뢰구간을 구분하여 표시한다.
    - 각 비율의 분모와 측정 구간을 명시한다. KPI는 이벤트·상태 기록을 기준으로 계산하고 화면 갱신 횟수에 의존하지 않는다.
    - 지도에는 정체·대기 위치를 표시하고, 표·차트에서 병목 위치와 원인 이벤트로 이동할 수 있게 한다.
    - **완료 기준:** 대기 원인별 시간 합계와 이벤트 로그를 대조할 수 있으며, 로봇 증차 또는 설비·버퍼 변경이 어느 지표에 영향을 줬는지 확인할 수 있다.

14. **시나리오 비교, 반복 실행 및 모델 검증**
    - AMR 대수·사양, 충전기 수·위치, 랙·버퍼 배치, 생산량, 배차·교통·충전 정책을 바꾼 시나리오를 저장하고 비교한다.
    - 시뮬레이션 기간, 초기 재고, 초기 로봇 위치·배터리, 진행 중 작업, 난수 시드 또는 시드 목록, 반복 횟수를 설정한다.
    - 각 반복은 동일하게 정의된 초기 상태에서 시작한다. 생산시간·고장·수요 등 변동 요인별 난수 흐름을 분리해 모델 변경에 따른 무관한 난수 교란을 줄인다.
    - 같은 시나리오의 반복 결과로 평균, 표준편차, 평균의 신뢰구간 등을 계산한다. 반복 횟수와 산출 방법을 기록하고 반복이 부족한 경우 신뢰구간을 임의로 제시하지 않는다.
    - 실제 하루·교대 운영 분석은 해당 시작 상태를 사용한다. 정상상태 분석은 필요 시 초기 안정화 구간을 별도로 설정하고 측정 구간에서 제외한다.
    - 실측 이동·도킹·상하차·생산시간과 실제 처리량·대기시간을 비교할 수 있게 한다. 실측 데이터가 없는 경우 입력 가정과 모델 검증 한계를 결과에 표시한다.
    - 로봇 1대, 단일 경로, 충전 경쟁, 교차로 경쟁, 버퍼 포화, 부품 부족, 설비 고장 등의 기준 시나리오로 동작을 검증한다.
    - **완료 기준:** 동일 조건 재현, 반복 실행 간 초기화, 정해진 기준 시나리오의 결과 확인이 가능하다. 시나리오별 차이와 난수에 따른 편차를 함께 비교할 수 있다.

15. **프로젝트 편집·저장·불러오기 및 로그 재현**
    - 프로젝트의 지도·배치·노드·경로, 로봇·설비 사양, 공정, 재고, 운영 정책, 시나리오를 구조화된 파일로 저장하고 불러온다.
    - 저장 형식은 고유 ID 참조와 스키마 버전을 포함한다. 불러오기 시 누락 참조·중복 ID·지원하지 않는 버전·단위 오류를 검증한다.
    - 편집 취소·다시 실행, 복사, 프로젝트 복제, 저장 전 변경 표시를 제공한다.
    - 1차 도면 입력은 PNG/JPG 등 배경 이미지와 축척·기준점 지정으로 구성한다. CAD 연계는 후속 범위로 분리해 변환 경로와 지원 형식을 결정한다.
    - 입력 설정·실행 조건·요약 결과·상세 이벤트를 JSON 또는 CSV로 내보낸다. 결과에는 프로젝트·시나리오·실행 ID와 모델·엔진 버전, 시드, 측정 구간을 포함한다.
    - 로그는 발생 시각, 이벤트 종류, 관련 작업·로봇·설비·운송물, 상태 변화와 원인을 포함한다.
    - 로그 재생은 기록된 상태를 사용하고 새로운 난수를 발생시키지 않는다. 저장된 입력으로 다시 계산하는 재실행과 기록된 실행을 보는 재생을 구분한다.
    - **완료 기준:** 저장 후 다시 연 프로젝트의 배치·설정·참조가 유지된다. 동일 조건 재실행과 기록 기반 재생이 가능하고, 내보낸 결과가 화면 결과와 일치한다.

구현은 다음 순서로 진행한다. 모든 번호는 최종 개발 범위에 포함하되, 1차에는 해당 항목의 기본 동작을 연결하고 후속 단계에서 정책과 예외를 확장한다.

| 단계 | 구현 범위 | 확인할 결과 |
| --- | --- | --- |
| 1차 통합 구현 | 2D 배치, DES 엔진, 기본 로봇 동작, FIFO 배차, 단일 통로·교차로 점유, 유한 버퍼, 기본 생산 이벤트, 기본 배터리·충전 대기, KPI, 저장·불러오기, 고정 시드 재현 | 생산 요청부터 운송·대기·충전·결과 조회까지 실제로 연결된 예제 |
| 2차 운영 확장 | 조립 부품 조건, 분포 확장, 다품종·배치, 엘리베이터·CTU·작업자, 배차·경로 정책 확장, 기회 충전, 장애·복구, 반복 비교·통계·로그 재생 | 설비 경쟁·부품 부족·장애와 정책 차이가 처리량·지연에 반영 |
| 후속 고도화 | 3D 표현, CAD 연계, 실운영 데이터·FMS·WMS·MES 어댑터, 자동 대안 탐색 | 추가 인터페이스·데이터와 검증 범위를 정한 뒤 구현 |

최종 제출물에는 실행 가능한 프로그램, 예제 프로젝트, 설치·실행 방법, 입력 항목 설명, 핵심 검증 결과, 구현 완료·미완료 항목 및 모델의 가정을 포함한다. 우선 1차 통합 구현을 실행 가능한 상태로 완성하고, 결과를 확인한 뒤 2차 기능을 추가한다. 도구나 기술 선택 때문에 범위를 바꿔야 하면 변경 항목과 영향이 문서에 남도록 한다.
