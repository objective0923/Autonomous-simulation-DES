## 추가 웹·수직 검토 범위

Three.js 3D, PDF 로컬 렌더링·2점 축척·기준점 저장, 1~100단 로봇/랙 측면도, 최소·최대 인계와 전고 구분, 빔 포함 높이·피치 검토, 2,699mm 예제와 mm JSON 가져오기, 규칙 기반 배치 후보를 추가했습니다. 실제 로봇 치수는 미제공 상태로 남겨 두고 예제 가정 입력을 구분합니다. 높이·하중 불합격 후보는 3D 검토할 수 있지만 2D 배치 적용은 차단합니다.

웹의 재생 정지와 서버 계산 중단을 구분합니다. 계산은 서버에서 마친 후 이력을 전달하며 웹에서 재생합니다. 요청 취소가 이미 진행 중인 SimPy 계산의 강제 종료를 의미하지 않습니다.

## 해석에 영향을 주는 제약

- 통로와 교차로를 **출발 시 경로 전체에 대해 원자적으로 예약**하고 도착 시 해제합니다. 여러 자원을 부분 보유한 채 서로 기다리는 교착을 만들지 않는 보수적 설계이며 현실 교통량을 과소평가할 수 있습니다. 일반적인 물리적 교착 탐지·우회 구현을 대신한다고 해석하면 안 됩니다.
- 지도에서 선이 교차하더라도 공유 노드나 `zoneId`가 없으면 독립 통로입니다. 실제 교차점은 `intersection` 노드로 분할하거나 공유 구역을 지정하세요.
- 상하차·대기 노드의 차체 정차 면적과 포트 외부 도킹 공간은 독립 유한 자원이 아닙니다. 버퍼 수량과 충전 포트·대기 수량의 용량은 계산합니다. 배치 객체는 장식/참조이고 객체의 width/height가 버퍼 용량으로 자동 변환되지 않습니다.
- 통로 장애는 동일 물리 구역을 공유한 양방향 표현에도 적용합니다. 고장 로봇의 운송물과 경로 점유는 유지하고 이동 표시를 고장 시점 위치에 고정합니다. 자동 견인이나 작업 재배차는 하지 않습니다.
- 배터리 고갈은 자동 복구하지 않는 예외입니다. 이미 적재한 운송물과 예약을 보존하며 결과의 진단에서 복구 필요 상태를 확인할 수 있습니다.
- 최대 충전 대기열과 버퍼 최대 물리 점유는 **전체 실행 구간** 기준이며, 이용률·상태별 시간·완료 처리량은 워밍업 이후 측정 구간 기준입니다.
- 공유 설비·장애 입력은 고급 JSON에서 설정합니다. 반복 통계는 CLI에서 제공합니다. 비교 목록은 브라우저 세션에만 유지되며 입력/결과 파일로 별도 저장해야 합니다.
- 이벤트 상태 이력을 메모리에 보관하므로 이 버전은 소규모 설계 비교에 적합합니다. 이벤트 한도 초과는 진단 오류이며 정상 완료로 해석하면 안 됩니다. 0초 순환 생산/운송 모델은 동일 시각 이벤트 한도로 중단될 수 있습니다.

CAD 의미 추출, 실장비 FMS/WMS/MES, SLAM, 센서, 모터 제어, 안전 인증은 후속/별도 범위입니다. 먼저 이 버전의 기준 예제와 데이터 형식을 유지하면서 위 확장을 추가할 수 있도록 UI·모델·엔진·분석을 분리했습니다.
